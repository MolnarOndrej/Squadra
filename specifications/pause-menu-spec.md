# Squadra mission pause menu

## Problem Statement

I want to interrupt a mission to take a break, adjust settings, or leave the mission safely. I need the game to stop while I use the menu, a clear indication that it is paused, and confirmation before I leave. I also want control over whether the game makes sound while I am using another application.

## Solution

Press Escape in a mission scene to freeze the game and dim the mission view behind a centered pause menu. Show **Paused** above **Resume**, **Settings**, **Quit to Menu**, and **Quit to Desktop**, in that order. Reuse the main menu's settings and feedback sounds. Require confirmation before either quit action. Allow the same pause menu over victory and defeat screens without losing the recorded result. Reuse their existing background dimming without darkening the screen further, temporarily hide the results panel while pause is open, and restore it unchanged on resume. Add a persistent **Mute in Background** checkbox to the shared Sound settings.

## User Stories

1. As a player, I want Escape to open the pause menu during a mission, so that I can take a break immediately.
2. As a player, I want production, fleet movement, combat, capture, and match time to stop while paused, so that the mission cannot change while I am away.
3. As a player, I want a dimmed mission view and a centered Paused heading, so that I can recognize the pause state and retain my place in the mission.
4. As a player, I want Resume or Escape to return to the same mission state, so that I can continue without restarting.
5. As a player, I want menu interaction to be isolated from gameplay, so that clicking a button cannot issue a fleet order.
6. As a player, I want visible mouse hover and keyboard focus with Resume focused initially, so that I can navigate the pause menu with either input.
7. As a player, I want Settings to offer the same General, Graphics, and Sound controls as the main menu, so that my preferences behave consistently.
8. As a player, I want Settings Back or Escape to return to the pause menu, so that adjusting settings does not resume the mission unexpectedly.
9. As a player, I want display changes to retain their timed confirmation while paused, so that I can recover from an unusable display configuration.
10. As a player, I want quieter mission music and normal menu feedback while paused, so that the pause menu is audible without the full gameplay mix.
11. As a player, I want gameplay effects to pause and music to return to its configured volume on resume, so that audio follows the game state.
12. As a player, I want volume changes made while paused to remain effective on resume, so that my adjustments are preserved.
13. As a player, I want Quit to Menu to ask for confirmation, so that an accidental selection does not abandon my mission.
14. As a player, I want Quit to Desktop to ask for confirmation, so that an accidental selection does not close the game.
15. As a player, I want Cancel or Escape to dismiss a quit dialog and leave the game paused, so that I can reconsider safely.
16. As a player, I want returning to the main menu to preserve victories recorded in this session, so that leaving a mission does not erase campaign completion.
17. As a player, I want to open pause over a victory or defeat screen and return to the same result, so that I can use Settings or quit without restarting the match.
18. As a player, I want the game to keep running when I switch away, so that changing applications does not automatically pause it.
19. As a player, I want a Mute in Background checkbox in either menu's Sound settings, so that I can silence the game while using another application.
20. As a player, I want background muting to work in every display mode and across all game audio, so that it behaves consistently when I Alt-Tab.
21. As a player, I want my background mute preference saved across launches, so that I only need to configure it once.
22. As a player, I want returning to the game to restore the correct audio mix, so that focus changes preserve my volumes and pause state.

## Implementation Decisions

- **Scope and relationship to the main menu.** Extend the existing mission presentation with a pause overlay. Reuse the UI Toolkit menu style, shared settings, and existing hover, selection, and back cues. This specification extends the main menu specification with in-mission navigation and background muting. Its return-to-menu behavior replaces the earlier limitation requiring a relaunch to leave a mission. Existing settings and campaign rules otherwise continue to apply.
- **Presentation.** Keep the current mission view visible under a full-screen translucent dark overlay, with the pause controls centered and Paused above them. When opened over victory or defeat, place the pause UI above the results layer and reuse its existing background dimming at the same opacity. Do not stack another dimming layer or darken the mission view further. Temporarily hide the results panel and disable its controls while pause, its Settings, or its confirmation dialogs are open, so results text and actions do not overlap the active menu. Resume restores the same results panel and its existing dimming unchanged. Use only one background dimming layer throughout this flow. Use the existing space-themed palette, readable labels, and visible hover and focus states. The overlay blocks interaction with everything beneath it. Settings and confirmations remain above the dimmed mission view.
- **Pause ownership and time.** Keep the pause state in the mission presentation/controller boundary, separate from the match result. Opening pause freezes simulation advancement, production, transit, arrival resolution, capture, match elapsed time, and gameplay presentation animations. It preserves the match, its current selection, and any existing result. UI navigation, menu feedback, mission music, and the display confirmation countdown remain functional using time independent of gameplay pause. Resuming must not advance simulation by time spent paused or replay queued gameplay inputs.
- **Opening, resuming, and input priority.** Escape opens pause whenever a mission scene is active, including over victory or defeat. Focus Resume initially. Resume or Escape on the root pause menu closes the pause UI and restores the previous mission or result screen. Remove the dimming when returning to a running mission; retain the existing results dimming when restoring a result screen. Escape now opens pause instead of performing the existing mission selection-cancel action; right-click and clicking the selected world still cancel selection. Consume each input once: an opening Escape cannot also resume, and menu input cannot trigger world selection, orders, or result replay. Block the existing click, R, Enter, and Space replay paths while the overlay or its child screens are open. Resume over a result restores that same result and its existing replay behavior without restarting the simulation.
- **Settings navigation.** Reuse General, Graphics, and Sound, including their defaults, supported platform options, local persistence, and audio preview behavior. The shared settings screen must support its calling menu as the return destination. Back or Escape from pause Settings returns to the root pause menu and leaves the mission paused. A quit dialog's Cancel or Escape also returns to the root pause menu. Nested controls and display confirmation consume Escape first: an expanded dropdown closes without leaving Settings, and Escape in a display confirmation reverts the preview and returns to Settings. A later Escape returns to pause. Keep the existing 12-second display confirmation deadline running while gameplay is paused, including when the application loses focus.
- **Pause audio.** Keep the mission track playing at 50% of the level produced by the current Master and Music settings throughout pause, Settings, and dialogs. Do not switch to the main menu track or restart the mission track. Pause active gameplay effects and prevent new gameplay effects while paused; restore their playback when gameplay resumes. Reuse the main menu feedback sounds at their normal configured Master and Sound Effects levels. Apply the music reduction as a temporary multiplier, without changing or saving a lower Music preference. Repeated pause cycles must not compound the reduction. On resume, remove the multiplier using the latest settings, including adjustments made while paused. Returning to the main menu removes the pause reduction and uses the existing main menu soundtrack behavior.
- **Menu feedback.** Reuse one hover cue per pointer entry on an enabled button, selection feedback for button or tab activation, and the distinct back cue for Back, Cancel, and Escape dismissal. Dismissal plays only the back cue. Pause does not silence these cues. Background muting, when enabled and unfocused, overrides them along with all other game audio.
- **Quit confirmations.** Quit to Menu and Quit to Desktop each open a modal identifying the destination, with Confirm and Cancel actions and Cancel focused by default. During an unfinished mission, explain that current mission progress will be lost. Over a result, explain the destination without falsely warning that an achieved victory will be discarded. Confine focus and interaction to the dialog. Cancel or Escape returns to pause without changing the mission, result, or campaign progress. Confirm executes the selected destination once; guard repeated activation during a scene transition or application exit.
- **Quit destinations and progress.** Confirming Quit to Menu unloads the mission and opens the initial main menu screen, rather than the mission map. Restore normal gameplay timing for later scene loads and remove mission-specific pause and audio state. Discard the current unfinished match without recording completion. Preserve settings, session campaign completion, and pending unlock reveals already recorded. A victory recorded before opening pause remains completed when leaving its results screen. Defeat does not add completion or erase earlier victories. Confirming Quit to Desktop closes the standalone game. Settings remain saved; campaign completion still lasts only for the application session, so a fresh launch starts a fresh campaign.
- **Mute in Background.** Add a checkbox with the exact label Mute in Background to shared Sound settings, available from the main menu and the pause menu. Default it to unchecked for a profile with no saved value. Apply and save a change on a completed toggle interaction, and load it with the other preferences before scene audio starts. The preference applies throughout the application, including menus, missions, results, and dialogs, in Windowed, Borderless Fullscreen, and Exclusive Fullscreen where supported. Define background as the game application lacking focus, including Alt-Tab or minimization.
- **Focus and audio composition.** Losing focus never automatically opens pause or resumes an already paused mission. Ensure an unpaused mission continues advancing while unfocused. With Mute in Background checked, silence all audio while unfocused, including music, gameplay effects, result cues, and UI feedback. Muting is an output override; it does not change saved volumes, pause the simulation, or restart tracks. On focus return, restore output using current preferences and state: full configured music during play, half configured mission music during pause, and gameplay effects still paused when appropriate. Unchecked leaves normal audio behavior in effect while unfocused. Compose focus muting with Master volume rather than allowing either operation to overwrite the other.

## Testing Decisions

- Use the playable mission and shared Settings UI as the primary integration test seam. Exercise the same input and navigation players use, asserting visible screens, public match state, scene transitions, campaign state, and audible behavior. Existing Edit Mode match and campaign tests provide prior art for assertions through public rule boundaries; retain them without testing private pause flags, internal timers, or audio object structure. This documentation change does not implement or run the future feature tests.
- Pause a mission with production, a fleet in transit, and capture underway. Wait longer than their normal completion intervals, navigate Settings and dialogs, and verify unchanged ship counts, positions, ownership, capture progress, match time, and gameplay presentation. Resume by button and separately by Escape; verify normal advancement without catch-up and preservation of the selected world.
- Verify button order, Paused heading, dimmed background, initial Resume focus, keyboard navigation, and pointer operation. Check that one Escape opens pause without cancelling selection or immediately closing it. Try world clicks and all result replay inputs under pause, Settings, and dialogs; none may affect the underlying mission. Check that activating Resume cannot also send an order or restart a result screen.
- Open each settings category from pause. Verify shared values, immediate audio preview, saving on completed interaction, and Back/Escape returning to pause. In a standalone build, exercise display confirmation, cancellation, Escape, and the 12-second timeout while gameplay stays frozen. Verify timeout and reversion still work after switching away. Check that dropdown dismissal consumes Escape without leaving Settings.
- Compare paused music against the configured mix: it is reduced to 50%, continues at the same playback position, and does not compound across repeated pauses or navigation. Verify gameplay effects pause while menu feedback remains audible. Change Master, Music, and Sound Effects while paused, resume, and verify the latest mix. Check that quitting to the menu starts its normal track without a residual pause reduction.
- Exercise both quit dialogs with Cancel and Escape, verifying focus confinement and an unchanged paused mission. Confirm Quit to Menu from an unfinished mission: the initial main menu appears, the match is abandoned without completion, prior victories and pending reveals remain, settings persist, and a newly launched mission advances normally. Verify Confirm cannot initiate duplicate navigation.
- In separate victory and defeat scenarios, open pause over the result, use Settings, dismiss both quit dialogs, and resume. Verify that opening pause does not darken the background further, that the results panel is hidden and its controls are inactive throughout pause and its child screens, and that closing pause restores the identical panel and dimming without restarting the match. Repeat pause/resume cycles to check for accumulated dimming or overlapping results text. Confirm Quit to Menu after victory and check its completion marker on the mission map; after defeat, check that no new completion was added and earlier completions remain. Check the dialog copy against whether the match is unfinished or already decided.
- In a standalone desktop build, separately confirm Quit to Desktop from a running mission and from a result. Verify the application exits, settings survive relaunch, and campaign progress resets on the fresh launch as specified.
- With a clean profile, verify Mute in Background is unchecked in both settings entry points. Toggle it in each, navigate between scenes, and relaunch; verify the same saved value. Test Alt-Tab, minimization, and focus return in each supported display mode, especially Borderless Fullscreen. When checked, all audio is silent while unfocused; when unchecked, audio follows the normal mix. In both cases, an unpaused mission continues and a paused mission stays paused.
- Test focus loss and return during gameplay, pause, pause Settings, results, and the main menu. Verify restoration honors zero volume, volume changes, and the 50% pause multiplier without restarting music or playing paused gameplay effects. Check repeated focus and pause cycles for a stuck mute or compounded reduction.
- Review at a typical desktop resolution and the supported minimum window size. Check heading and button readability, modal layering over results, visible keyboard focus, and unobstructed settings and confirmation controls.

## Out of Scope

- Implementing the feature as part of this specification change.
- Save games, restoring abandoned matches, or campaign completion across application launches.
- A new results screen, a new Continue flow, or changes to victory, defeat, replay, combat, production, or capture rules.
- Restart, mission selection, or other additional pause menu actions.
- Automatic pause on focus loss, multiplayer pause, controller support, and new key-binding settings.
- New menu music, new UI sound assets, additional settings categories, languages, or platform support beyond the existing desktop targets.

## Further Notes

- Product decisions were agreed in the pause menu interview. No open product decisions remain.
- Implementation assumptions to validate: shared Settings currently depends on the main menu host and will need a reusable navigation/dialog boundary; existing scene presentation uses both scaled and unscaled time, so stopping simulation alone may not freeze all mission visuals. Validate pause across those paths without freezing UI deadlines or music.
- The current result interaction accepts a broad click or key press to replay. Validate input consumption carefully when pause opens or closes over results.
- Validate background execution and focus callbacks in standalone builds; Editor focus behavior is not sufficient evidence for Alt-Tab behavior. If a focus change accompanies display preview, retain its real-time timeout and rollback behavior.
- No exact dimming opacity or transition duration was requested. Match the existing menu's visual language and verify readability rather than treating an arbitrary value as a product requirement.
